Non-Functional Requirements

1. Introduction

Non-functional requirements describe the quality attributes and operational constraints of the University Library Management System.

The following requirements are preliminary proposals. Where measurable targets are suggested, the project team must confirm their suitability before finalizing them.

2. Non-Functional Requirements

Requirement ID	Category	Requirement
NFR-01	Security	The system shall restrict protected functions to authenticated users with appropriate permissions.
NFR-02	Privacy	The system shall restrict access to student information according to assigned user permissions.
NFR-03	Usability	The system shall provide a clear and consistent interface with understandable labels and navigation.
NFR-04	Data Accuracy	The system shall validate borrowing and return transactions to help maintain accurate library records.
NFR-05	Reliability	The system shall preserve confirmed transactions and provide a recovery procedure for data loss incidents.
NFR-06	Performance	Common operations, such as book searches, should return results within an agreed response-time target under normal operating conditions.
NFR-07	Maintainability	The system’s code and documentation shall be organized so that developers can understand and maintain the software.
NFR-08	Backup and Recovery	The system shall have a defined procedure for backing up and restoring library data.
NFR-09	Compatibility	The system shall support the browsers and operating environments agreed upon by the project team.
NFR-10	Access Control	The system shall prevent users from performing operations outside their assigned permissions.

3. Quality Attributes

Security

Only users with appropriate authorization should be able to access protected functions and records.

Usability

Users should be able to navigate the system and understand its main functions without unnecessary complexity.

Reliability

The system should handle library transactions consistently and provide a suitable recovery process.

Performance

The team should establish measurable response-time targets based on expected system usage and available resources.

Maintainability

The software should be organized and documented so that future changes can be made efficiently.

4. Review Status

Status: Preliminary.

The project team must agree on measurable targets, supported environments, and operational constraints before implementation.

5. Conclusion

These non-functional requirements establish initial expectations for security, privacy, usability, reliability, performance, and maintainability. They will be reviewed and refined during requirements analysis.
